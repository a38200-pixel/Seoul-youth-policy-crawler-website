# 알려진 한계 (Known Issues 전체)

README 본문에는 이 중 일부만 적었습니다. 수치마다 기준 날짜를 함께 적었고, 확인하지 못한 것은 확인하지 못했다고 적었습니다. **가설**은 검증하지 않은 해석입니다.

## 수집과 운영

1. 공고 변경은 하루 1회(07:00) 수집 시점에 반영됩니다. 사이트 구조(셀렉터)가 바뀌면 수집이 깨질 수 있습니다. 목록이 0건이면 DB 를 건드리지 않고 종료 코드 2 로 끝납니다.
2. 자동 수집은 **PC 가 켜져 있고 로그인된 상태**여야 하며, 꺼져 있던 날은 수집 공백이 생길 수 있습니다. 작업 스케줄러의 "놓친 실행을 가능한 한 빨리 시작" 옵션은 설정만 했고 동작은 확인하지 못했습니다([scheduler.md](scheduler.md)).
3. 자동 실행 기록은 2026-10-04~10-06 3회뿐이라 장기간 안정성은 확인하지 못했습니다.
4. 상시 공고 7일 갱신은 구현과 테스트만 했고 실제로 발동한 적이 없습니다(2026-10-06 기준 `--daily` 로그 6개 모두 "상시 갱신 0건"). 첫 발동은 2026-10-09~10-10 쯤으로 예상하며 확인하지 않았습니다. 50% 검사에 걸린 적도, 상세 연속 실패로 중단된 적도 없습니다([daily_crawl_policy.md](daily_crawl_policy.md)).
5. 활성 상시 공고 중에는 진행일정이 이미 끝난 것이 상당수 포함되어 있습니다. 개발용 복사본 2026-10-04 기준 활성 상시 1,068건 중 진행일정(`schedule_text`)의 마지막 날짜(범위면 `~` 뒤의 날짜, 아니면 앞의 날짜)가 2026-10-04 이전인 것이 560건입니다. 날짜가 없어 파싱하지 못한 354건(`상시` 등)은 제외했고 파싱에 성공한 것은 714건입니다. 이 1,068건이 화면의 상시·기타 탭 합계(922 + 146)와 같은 집합으로 추정되지만 이 일치는 확인하지 않았습니다. 화면에서 어떻게 다룰지는 정하지 않았습니다.

## 변경 감지

6. 변경 이벤트 종류 중 마감 연장(`extended`), 마감 단축(`shortened`), 신청기간 변경(`period_changed`), 다시 게시됨(`reactivated`)은 **지원하지만 실제로 한 번도 발생하지 않았습니다**(2026-10-06 기준 DB 의 변경 이벤트 73건은 `deactivated` 68건과 `status_changed` 5건뿐). 단위 테스트로만 확인했습니다. 관찰한 표본 기간도 2026-10-02~10-06 로 짧습니다.
7. 목록에서 사라진 공고의 구분(`expired`/`early`)은 사이트가 알려 준 이유가 아니라 **마감일과 사라진 시점을 비교해 계산한 값**입니다.
8. 기준일(2026-10-01)에 처음 적재한 공고는 NEW 로 표시하지 않습니다. 재분류(`--reclassify`)는 변경 이벤트를 만들지 않습니다.
9. 모집상태가 '모집예정'인 `end_only` 공고는 시작일을 몰라 '시작 D-n' 을 만들 수 없습니다. 화면은 백엔드의 표시 규칙대로 마감 D-Day 로 보여 주고, 사이트 상태는 상세 패널의 '사이트 상태'에 그대로 표시합니다.
10. 다음은 **가설**이며 아직 검증하지 않았습니다(근거와 검증 기준은 [devlog.md](devlog.md) 3번·12번 항목).
    - 상시 공고가 마감일 전에 내려가는 원인은 확정하지 못했습니다. 복사본 2026-10-04 기준 비활성 상시 11건은 모두 `source_id` 가 64727 이하이고 활성 상시 1,068건은 모두 64782 이상이라, ID 순서로 오래된 것부터 사라진 것으로 보입니다. 다만 이는 ID 가 등록 순서를 반영한다는 미검증 가정 위의 해석이며, 사이트의 등록일은 DB 에도 없고 크롤러도 읽지 않습니다.
    - 신청기간이 불완전한 글(시작일만 또는 종료일만 있는 글)은 1~2일 안에 사라지는 경향(9건 중 9건, 표본 작음).

## API

11. API 에는 인증이 없고 읽기 전용입니다. CORS 는 `localhost:5173`, `127.0.0.1:5173` 만 허용합니다. 배포하지 않았고 로컬에서만 실행합니다.
12. `/api/changes` 는 페이지 나누기 기능이 없어 화면에서 50건씩 나눠 보여 줍니다. "오늘 마감" 펼치기는 한 번에 최대 200건(API `limit` 상한)입니다.

## 화면

13. 구글 캘린더에 추가한 일정은 추가한 시점의 마감일 기준이며 이후 변경은 자동 반영되지 않습니다. 이 화면은 사용자의 구글 계정에 접근하지 않고 아무것도 저장하지 않습니다. 모바일 실기기에서 이 링크가 동작하는지는 확인하지 않았습니다.
14. 프런트 린트(oxlint) 경고 2건이 남아 있습니다(`frontend/src/api/hooks.ts` 25·26줄, 2026-10-06 `npm run lint` 로 다시 확인).
15. 모바일 실기기, 스크린리더 실사용, 글자 대비의 도구 측정은 하지 않았습니다.
16. '마감일 미정' 섹션은 개발용 복사본에 해당 공고가 0건이라 실데이터로 화면을 확인하지 못했습니다(모의 데이터 테스트로만 확인). 2026-10-06 기준 DB 에도 활성 `open` 공고는 0건입니다.
17. '확인 필요'(`unknown`) 공고는 어느 탭에도 나오지 않습니다(화면이 `tab=all` 을 쓰지 않음). 2026-10-06 기준 DB 에는 활성 `unknown` 공고가 0건입니다.

## 저장소

19. `requirements.txt` 가 버전을 고정하지 않았고, 파이썬·Node 의 최소 요구 버전을 정한 파일이 없습니다([setup_and_run.md](setup_and_run.md)).
