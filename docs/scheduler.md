# 자동 수집 (Windows 작업 스케줄러)

매일 07:00 에 `--daily` 수집을 실행하는 Windows 작업 스케줄러 작업의 설정과 결과입니다. 설정은 2026-10-06 에 작업을 읽기 전용으로 조회해 확인했습니다. 로컬 경로와 사용자 이름은 적지 않았습니다.

## 작업 설정

| 항목 | 값 |
|---|---|
| 작업 이름 | `SeoulYouthDaily` |
| 실행 시각 | 매일 07:00 (하루 간격 트리거) |
| 실행 제한 시간 | 2시간 |
| 동작 | conda 환경(`web_crawling`)의 `python.exe` 를 직접 호출. 인자: `-m backend.crawler.crawl --daily --headless` |
| 시작 위치(작업 디렉터리) | 프로젝트 루트(저장소 최상위 폴더). `-m backend.crawler.crawl` 은 프로젝트 루트에서 실행해야 합니다 |
| 로그온 방식 | 대화형(사용자가 로그온한 상태에서 실행), 실행 수준 제한 |
| 중복 실행 | 이미 실행 중이면 새 실행을 시작하지 않음(`IgnoreNew`) |
| 놓친 실행 | "가능한 한 빨리 시작" 옵션이 켜져 있음(`StartWhenAvailable = True`). **이 옵션이 실제로 동작하는지는 확인하지 못했습니다**(놓친 실행이 한 번도 없었음) |

## 실행 결과

2026-10-06 조회 기준 마지막 실행은 2026-10-06 07:00:01 이고 작업 결과 코드는 0, 놓친 실행 횟수는 0, 다음 실행 예정은 2026-10-07 07:00 입니다.

| 실행일 | 시작 | 소요 | 상세 성공 / 실패 | WARNING·ERROR | 활성 공고 (전 → 후) | 새로 비활성 |
|---|---|---|---|---|---|---|
| 2026-10-04 | 07:00:04 | 877.0초 | 432 / 0 | 0건 | 1,502 → 1,500 | 2건 |
| 2026-10-05 | 07:00:04 | 855.3초 | 427 / 0 | 0건 | 1,500 → 1,495 | 5건 |
| 2026-10-06 | 07:00:05 | 790.0초 | 404 / 0 | 0건 | 1,495 → 1,472 | 24건 |

출처: 각 날짜의 수집 로그(`backend/logs/crawl_YYYYMMDD.log`)의 요약 줄. 3회 연속 정상 종료했습니다. 이 기록이 쌓인 기간은 3일이라 장기간 안정성은 확인하지 못했습니다.

## .bat 대신 python.exe 를 직접 호출하는 이유

- 처음에는 [scripts/run_daily.bat](../scripts/run_daily.bat) 을 스케줄러에 연결했습니다.
- 작업 결과 코드가 `3221225477`(0xC0000005)로 나왔습니다.
- Windows 이벤트 로그에서 종료된 프로그램은 파이썬이 아니라 `cmd.exe` 였습니다. 같은 `.bat` 은 일반 터미널에서는 정상 동작했고, 크롤 로그에는 이 시도의 실행 기록이 남지 않았습니다(파이썬이 시작되기 전에 멈춘 것으로 보임).
- **원인은 확정하지 못했습니다(원인 미확정).**
- 작업 동작을 `python.exe` 직접 호출로 바꾼 뒤 정상 동작했습니다. `run_daily.bat` 은 수동 실행용으로만 남겼습니다.

작업 스케줄러라는 방식을 고른 이유는 문서에 기록이 없어 적지 않았습니다.

## 한계

- **PC 가 켜져 있고 로그인된 상태여야 실행됩니다.** 꺼져 있거나 로그인되지 않은 날은 실행되지 않아 수집 공백이 생길 수 있습니다.
- 앞서 적은 대로 "놓친 실행을 가능한 한 빨리 시작" 옵션은 설정만 했고 동작은 확인하지 못했습니다.
- 사이트 구조(셀렉터)가 바뀌면 수집이 깨질 수 있습니다. 목록이 0건이면 DB 를 건드리지 않고 종료 코드 2 로 끝납니다.
